# MyCoffee

Веб-система управленческого учета для кофейни формата «с собой». Проект изначально создается так, чтобы работать на обычном shared-хостинге Beget без Docker, Node.js и обязательного Composer.

## Стек

- PHP 8+
- MySQL / MariaDB
- HTML/CSS
- минимальный JavaScript по мере необходимости
- Apache / `.htaccess`

## Уже реализовано

- установка через браузер;
- авторизация владельца;
- финансовый дашборд;
- выручка, количество чеков и средний чек;
- себестоимость проданных товаров;
- валовая и операционная прибыль;
- ингредиенты и закупочные цены;
- меню и техкарты;
- автоматический расчет себестоимости позиции;
- ручной ввод продаж;
- закупки и расходы;
- интеграционный слой Эвотор;
- автоматический импорт номенклатуры Эвотор;
- автоматический импорт продаж `SELL` и возвратов `PAYBACK`;
- сохранение исходного JSON документов Эвотор;
- журнал синхронизаций;
- cron-синхронизация для Beget.

## Установка на Beget

1. Создать сайт/домен и базу MySQL в панели Beget.
2. Загрузить содержимое репозитория в корневую папку сайта.
3. Убедиться, что используется PHP 8.0+ и доступны расширения PDO MySQL, cURL и OpenSSL.
4. Открыть сайт в браузере. При отсутствии `config.php` откроется `install.php`.
5. Ввести хост, имя БД, пользователя и пароль базы, затем создать учетную запись владельца.
6. После установки войти в систему.

`config.php` создается на сервере, содержит случайный ключ шифрования и исключен из Git через `.gitignore`.

## Интеграция с Эвотор

Откройте **Интеграции → Эвотор**, вставьте токен пользователя Эвотор и при необходимости ID магазина. Если токен имеет доступ только к одному магазину, система попробует определить его автоматически.

Токен Эвотор хранится в MySQL в зашифрованном виде AES-256-GCM. Ключ шифрования хранится только в `config.php` на сервере.

Во время полной синхронизации система сначала загружает номенклатуру, затем документы продаж и возвратов. Исходные документы сохраняются отдельно, а `SELL` и `PAYBACK` преобразуются в записи `sales` / `sale_items`, поэтому основной финансовый дашборд работает с данными кассы автоматически.

Синхронизация инкрементальная: после первого запуска запрашиваются только объекты, созданные или измененные после последней успешной точки синхронизации. Повторный импорт одного и того же документа защищен уникальным ID документа Эвотор.

### Cron на Beget

После подключения Эвотор добавьте задание Cron в панели Beget. Рекомендуемый интервал для начала — раз в 5 минут.

Команда зависит от пути к сайту и версии PHP в аккаунте. Логика запуска должна соответствовать:

```bash
php /полный/путь/к/сайту/cron/evotor_sync.php
```

`cron/evotor_sync.php` разрешает запуск только из CLI, поэтому вызвать синхронизацию через браузер нельзя.

## Архитектура данных Эвотор

- `evotor_connections` — подключенные магазины и зашифрованные токены;
- `evotor_products` — номенклатура и соответствие локальным товарам;
- `evotor_documents` — неизмененная копия кассовых документов и связь с локальной продажей;
- `evotor_sync_log` — журнал запусков синхронизации.

Это позволяет в будущем менять алгоритмы аналитики без потери исходных кассовых данных.

## Принцип продукта

Главная задача MyCoffee — не просто хранить таблицы, а отвечать владельцу на четыре вопроса:

1. Сколько заработала кофейня?
2. Почему именно столько?
3. Где теряются деньги?
4. Что стоит изменить сегодня?
