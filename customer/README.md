# Клиентская часть Kapouch

Папка `customer/` специально не использует админский `inc/layout.php` и не обращается к базе напрямую.

## Сейчас

Поток: каталог → корзина → самовывоз → заказ в live-экране бариста → публичное отслеживание статуса.

Клиентская часть обращается только к API:

- `GET api/customer_catalog.php`
- `POST api/customer_order.php`
- `GET api/customer_order_status.php?token=...`

## Перенос на другой домен

1. Скопировать содержимое `customer/` на новый сайт.
2. В `customer/config.js` заменить `apiBase` на абсолютный адрес API Kapouch.
3. В Kapouch задать настройку `customer_api_allowed_origin` равной origin клиентского сайта, например `https://order.example.ru`.

После этого фронтенд может жить отдельно от Kapouch.

## Безопасность заказа

Фронтенд отправляет только `product_id` и количество. Название, доступность и актуальная цена позиции заново читаются из базы Kapouch на сервере. Итоговая сумма не принимается от браузера.

Публичное отслеживание использует случайный 64-символьный `tracking_token`, а не внутренний ID или легко угадываемый номер заказа.

## Следующие этапы

Таблицы `customer_accounts` и `customer_loyalty_ledger` уже создаются миграцией 017. На их основе можно добавить вход по телефону, историю заказов, бонусный баланс, начисление/списание и уровни программы лояльности без изменения текущего API заказа.
