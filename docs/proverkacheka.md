# ПроверкаЧека.com в Kapouch

Kapouch использует официальный API endpoint сервиса:

`POST https://proverkacheka.com/api/v1/check/get`

В запрос передаются фискальные реквизиты из QR (`fn`, `fd`, `fp`, `t`, `s`, `n`), признак `qr=1` и API-токен пользователя. Сервис в успешном ответе возвращает `code=1`, а данные чека находятся в `data.json`.

В Kapouch токен вводится только на странице `Закупки → ПроверкаЧека.com` и хранится в зашифрованном AES-GCM виде в существующей таблице `receipt_data_connections`.

Внутренний `receipt_proverkacheka_proxy.php` нужен для совместимости с универсальным механизмом источников чеков Kapouch. Он:

1. принимает запрос только с сохранённым Bearer-токеном;
2. сверяет токен с зашифрованной настройкой Kapouch;
3. отправляет POST-запрос в ПроверкаЧека.com;
4. проверяет `code=1`;
5. возвращает в мастер закупок только объект электронного чека из `data.json`.

Токен не выводится в интерфейс, логи и ответы proxy.

После подключения рабочий сценарий: `QR → ПроверкаЧека.com → позиции чека → черновик → исключение личных покупок → сопоставление ингредиентов → приход на склад`.
