# Клиентский PWA на app.kapouch.store

Целевая схема:

- `https://kapouch.store/` — админка Kapouch, API, Evotor, cron и webhooks.
- `https://app.kapouch.store/` — клиентский PWA.
- Старый `https://kapouch.store/customer/` временно остаётся рабочим на этапе перехода.

## Beget: привязка поддомена

`app.kapouch.store` должен быть прикреплён к тому же сайту (директории), что и `kapouch.store`, то есть к существующему сайту `kapouch.store/public_html` в терминах панели Beget.

Не нужно копировать файлы PWA в отдельный `app.kapouch.store/public_html` и не нужно настраивать внешний 301/302 редирект.

Корневой `.htaccess` различает домены по `HTTP_HOST`: запросы к `app.kapouch.store` внутренне переписываются в каталог `customer/`, поэтому адрес в браузере остаётся `https://app.kapouch.store/...`. Через клиентский поддомен запрос к `/index.php`, `/settings.php`, `/inc/...` и другим путям основного проекта не открывает админку: он ищется только внутри `customer/` и либо обслуживает PWA, либо возвращает 404/403.

PWA на новом origin обращается к API только по `https://kapouch.store/api`. API разрешает точный origin `https://app.kapouch.store`; произвольные внешние origin по-прежнему блокируются.

## Порядок переключения в Beget

1. В разделе «Сайты» открепить `app.kapouch.store` от отдельного сайта `app.kapouch.store/public_html`.
2. В строке существующего сайта `kapouch.store/public_html` выбрать «Прикрепить домен» и выбрать `app.kapouch.store`.
3. Не удалять DNS-запись и SSL. После перепривязки Beget может применять изменение около 10 минут.
4. Открыть `https://app.kapouch.store/` и убедиться, что в адресной строке остаётся именно поддомен без `/customer/`.

## Проверка до переключения клиентов

Проверить `https://app.kapouch.store/`: каталог, SMS-вход, профиль, QR-карту, юридические документы, корзину, оформление наличного заказа, статусы, push и установку PWA.

На этом этапе публичный QR и старые ссылки можно не переключать. После успешной проверки отдельным изменением переводятся QR/админские ссылки и return URL онлайн-оплаты, а старый `/customer/` получает безопасный переход на новый адрес.
